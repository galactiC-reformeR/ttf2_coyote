        为什么不用读屏？
        血条像素会被画面设置、分辨率、HUD 缩放和叠加层影响，误判代价直接落在身上。数值变化是确定的，直接读数值。
      

    

  


  
  

    

      

        
通道映射

        
三个条目，两种输出形态

        
持续型和脉冲型各占一条通道：它们操作同一条强度层，压在一起会互相覆盖，所以插件自己强制分家。

      


      

        

          
A
血量档位
电平 · 持续

          
血量跨过阈值才改强度，一直保持。70% / 50% / 30% / 濒死四档，默认 20 / 30 / 40 / 60。

          
    
            
  • 回血按新档位重新输出，本身不发脉冲
    • 
            
  • 2% 滞回，避免临界点反复横跳
    • 
            
  • 泰坦被毁那一帧不会误判成巨额受击
    • 
          

        


        

          
B
单次受击
脉冲 · 可关

          
一次掉血给一次脉冲，默认强度 25、时长 300ms，可单独关掉。

          
    
            
  • 单次掉血 ≥ 1500 才触发，滤掉散弹弹丸与环境伤害
    • 
            
  • 1 秒内累计 ≥ 2000 也算一次，覆盖连打
    • 
            
  • 频率上限约 3.3 次/秒，在途的伤害合并成一次
    • 
          

        


        

          
E
死亡脉冲
脉冲 · 独占

          
死亡界面出现后给一次持续输出，默认强度 45、时长 5 秒，0.5 到 15 秒可调。

          
    
            
  • 任何死亡界面都发，步行阵亡也一样
    • 
            
  • 泰坦被毁那一帧标志位只抖 0.3 秒，内置 500ms 去抖挡掉误触发
    • 
            
  • 波形留空 = 恒定，也可以自己选
    • 
          

        

      


      

        

          
规则：一组一条通道

          
持续输出必须独占一条通道，受击与死亡脉冲可以合用另一条（它们不会同时发生）。把脉冲选到持续通道上时，插件按持续输出优先处理，脉冲自动改用另一条，并把界面上的值改回实际值，同时写一条 warning 说明原因。

        

        

          
改通道即时生效

          
切换通道时插件先把两条通道归零，再按新映射重新下发，不会把上一次的档位强度残留在被释放的通道上。模拟模式下重叠则直接拒绝本次演练输出，方便你在真机之前就发现配错。

        

      

    

  


  
  

    

      

        
档位与强度

        
换算只有一个公式

        
pct = 郊狼值 × 100 ÷ 该通道上限。上限取错会让所有强度按比例偏移，所以上限不可配置，只有设备上报和固定 100 两个来源。

      


      

        

          
            
血量档位触发条件默认强度（郊狼值）输出形态

          
          
            
70%血量低于最大血量 70%20电平保持

            
50%血量低于最大血量 50%30电平保持

            
30%血量低于最大血量 30%40电平保持

            
濒死标志位成立且血量 ≤ 25%，或最大血量塌缩60电平保持

            
受击单次 ≥ 1500 或 1 秒累计 ≥ 200025脉冲 300ms

            
死亡死亡界面标志稳定 500ms45脉冲 5000ms

          
        

      


      

        

          
换机体不用改配置

          
判定按比值做，不认绝对血量。五种机体真实最大血量 7500 / 10000 / 12500 / 15000 / 17500 全部适用，3 到 7 格血条都能打。

        

        

          
濒死用双判据

          
标志位是位域而不是布尔：同一局里实测到正常 2 → 濒死 3、正常 0 → 濒死 1，所以按掩码比较。再加一道血量门槛和"最大血量塌缩"判据，覆盖"上机时人已经在濒死泰坦里"。

        

        

          
上限只在注册时上报

          
DGHub 只在插件注册那一刻推一次设备信息。上报失败时插件按固定 100 换算，与郊狼 V3 实际上限一致。想要最准的换算，就在郊狼已连接的状态下启用插件。

        

        

          
插件自身上限 80

          
任何条目都不会超过插件自身上限（默认 80，可改）。日志里 cfg 是你配的值，eff 是实际下发的值，两者不等时 clamp 会写明被谁削顶。

        

      

    

  


  
  

    

      

        
特性

        
踩过的坑都焊死在代码里

        
以下每一条都来自实机故障，不是纸面设计。

      


      

        

          ◆
          
内存定位已内置

          
地址写在代码里，装完就能用，不用 Cheat Engine、不用填偏移。配置页里已经没有"内存定位"区。

        

        

          ◆
          
只读，不注入

          
只申请 PROCESS_VM_READ，绝不写游戏内存，也不往游戏里挂任何东西。

        

        

          ◆
          
fail-closed

          
读到无效数据时不产生任何脉冲，宁可漏报绝不误报。连续 5 帧无效才提示，恢复稳定 3 秒后自动撤销。

        

        

          ◆
          
重连自愈

          
郊狼断开再连上后不需要关开插件：每 3 秒幂等重发当前输出，脉冲在途时自动延后，值没变化设备侧完全无感知。

        

        

          ◆
          
演练模式

          
一个包都不发，只把"本来会下发的命令"写进日志，波形名和换算后的百分比都能先核对。

        

        

          ◆
          
无游戏也能验证

          
模拟数据源把 17 个战斗剧本按真实时间轴回放，每步都配中文解说，播完就停。

        

        

          ◆
          
进程自检

          
读不到数据时插件自己查进程，把"没启动 / 引擎没加载 / 附错进程 / 名字不对"六种情况分别写进日志。

        

        

          ◆
          
离线回归

          
17 个黄金场景 + 17 个会话用例，不接游戏、不接设备就能跑，改判定逻辑不会被旧行为偷偷救回来。

排查

        
没有输出时，先看日志这一行

        
变更日志按 (slot, cfg, eff, clamp, reason) 各字段变化时输出一行，reason 会直接告诉你为什么是这个值。

      


      

        
[12.3] hp=7800/12500 doomed=0 peak=12500 titan=1 alive=1 | ch=a slot=A_70 cfg=20 eff=20 clamp=- reason=tier-enter
[13.1] hp=2400/12500 doomed=1(collapse) peak=12500 titan=1 alive=1 | ch=a slot=A_DOOM cfg=60 eff=60 clamp=- reason=tier-enter
[14.0] hp=2500/2500  doomed=1(flag)     peak=2500  titan=1 alive=1 | ch=a slot=A_DOOM cfg=60 eff=60 clamp=- reason=tier-enter

        
doomed=1(flag) 表示濒死由标志位判定，(collapse) 表示由最大血量塌缩判定；peak 是本次驾驶记录到的血量峰值。

      


      

        

          完全没有输出按顺序看
          

            

              
                
日志每条都带 [演练] 待下发演练模式还开着，插件一个包都没发 → 关掉演练模式

                
日志写 数据源：模拟数据源数据源还是剧本，压根没读游戏 → 切成内存只读轮询

                
日志写 内存字段未标定内置定位读不到（引擎版本变了）→ 跑 tools\calibrate.py 重新定位

                
日志写 reason=no-titan 或 reason=idle这是正常的没有输出：不在泰坦里，或血量还在最高档之上

                
强度只有配置的一半上限按 200 换算导致整体减半 → 在郊狼已连接时重新启用插件

                
日志写 设备未连接郊狼没连上，或没在插件上重新选输出目标

              
            

          

        


        

          连续读到无效数据四种原因
          

            
连续 5 帧读数被判无效时触发，每 30 秒最多一条，恢复稳定 3 秒后自动撤销。日志会把是哪一条挂了、读的是哪个进程、最近一帧长什么样一起写出来。

            

              
                
最大血量<=0不在对局 / 主菜单 / 没坐进泰坦，属正常；一直在泰坦里仍为 0 才需要重新标定

                
血量超范围 / 单次变化超过最大血量地址错位，引擎构建变了 → 重新标定

                
读取失败游戏进程关了，或句柄 / 模块基址失效 → 重启插件

              
            

          

        


        

          郊狼重连后没输出已修
          

            
老版本按 (档位, 强度) 去重下发：设备断开期间强度层实际值已归零，但插件缓存没变，于是从此不再下发。现在按 3 秒定期幂等重发，断开重连后最迟一个周期内自动恢复，不用关开插件。

            
顺带说明：日志里 设备目标不可用，命令已丢弃 不是错误，只表示那一刻郊狼没连上。

FAQ

        
常问的几个问题

      


      

        

          会不会写游戏内存？算不算外挂？
          
插件只以只读权限打开游戏进程，读几个数值，不写入、不注入 DLL、不修改游戏文件、不读屏幕。它取得的信息与你眼睛看到血条是同一件事，只是更精确。

        

        

          需要装 Python 或者 Cheat Engine 吗？
          
都不需要。插件进程由 DGHub 以 DGLab-Console.exe --plugin-runner main.py 拉起，用的是 DGHub 内嵌的 CPython。Cheat Engine 只在你自己重新标定内存地址时才用得上。

        

        

          游戏更新之后还能用吗？
          
内置地址是静态地址（在 engine.dll 数据段，重启游戏、换电脑都不变），但引擎二进制一变就要重新定位。跑一条 python tools\calibrate.py --minutes 4 按提示在控制台打几下伤害，工具会输出新地址；写进 D:\dghub\config.json 本插件段的同名键即可，配置文件的值优先于内置值，不用改代码也不影响下次更新版本。

        

        

          我还没买游戏，能先看看效果吗？
          
能。数据源切「模拟数据」，打开「输出变更日志」，选剧本 S1，插件会把血量从 68% 一路掉到濒死的完整过程按真实时间轴回放，每一步配一句中文解说。想连设备实际感受的话，把「演练模式」关掉就是真实下发。

        

        

          处决动画期间会给脉冲吗？
          
不会额外给。处决动画期间插件保持濒死档持续输出，受击脉冲照常判断，死亡脉冲只由死亡界面触发，所以己方处决敌方泰坦不会误吃一次死亡脉冲。

        

        

          为什么体感强度和面板数字对不上？
          
先看日志里 cfg 与 eff 是否相等，clamp 会说明被谁削顶。再看上限：换算公式是 郊狼值 × 100 ÷ 通道上限，上限取 200 会让所有强度直接减半，所以要确保郊狼已连接后再启用插件。
