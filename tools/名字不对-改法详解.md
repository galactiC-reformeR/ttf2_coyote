# 「名字不对」这类问题的改法详解（四种典型情况）

对象：`ttf2_coyote` v2.20.3 的 `⚙️ 基础与数据源 → 进程 / 默认模块名`
适用：exe 被换成启动器、副本改名、被杀软加后缀、壳自己的名字

## 先记住三条硬规则

1. **只填文件名**，不填路径、不填引号。`D:\STEAM\...\Titanfall2.exe` ❌ ／ `Titanfall2.exe` ✅
2. **大小写不敏感**（`titanfall2.exe` 也能命中），但**全角/半角、空格、括号必须一模一样**
   （代码里是字符串相等比较，只做了 `strip()` 去首尾空白）。
3. **改完即时生效，不用重启插件**：`mem_module` 在 `SOURCE_KEYS` 里，改它会触发数据源重建
   （`_rebuild_source_now` → `_open_source`），旧句柄会被关掉、按新名字重新附加。

改之前先确认引擎宿主是谁（规则：**哪个进程加载了 `engine.dll` 就填哪个**）：

```pwsh
python tools\probe_process.py
```

它的输出会直接告诉你填什么，并附抄写提示：

```
  TF2_CN.exe      pid=24120  窗口=True   engine.dll=0x7FF6...
                  8 字符，含非 ASCII（中文/全角），必须原样照抄
  引擎宿主进程：TF2_CN.exe（pid 24120）
  → 「进程 / 默认模块名」填：TF2_CN.exe
    （原样 8 个字符，不带路径、不带引号；改完即时生效、不用重启插件）
```

## 情况一：主 exe 被换成第三方启动器

**典型现象**：游戏目录里没有 `Titanfall2.exe`，只有一个 `开始游戏.exe` / `Play.exe` / `TF2启动器.exe`；
双击它能进游戏，但插件报 `自检：没找到游戏进程…`。

**要看清楚的是**：启动器**不等于**引擎宿主。两种结构完全不同的改法：

| 结构 | 怎么判断 | 该填什么 |
|---|---|---|
| 启动器**只是拉起**游戏，引擎在子进程里 | `probe_process.py` 输出里 `开始游戏.exe` 那行 `engine.dll=未加载`，另有某个进程 `engine.dll=0x…` | 填**那个子进程**的名字（常常还是 `Titanfall2.exe` → 那就不用改，`auto` 本来就能命中） |
| 启动器**把引擎装在自己进程里**（打包器/壳） | `开始游戏.exe` 那行就有 `engine.dll=0x…` | 填 `开始游戏.exe`（宿主就是它） |

**例子**
```
你的输出：
  开始游戏.exe  pid=8800  窗口=False  engine.dll=未加载
  开始游戏.exe  pid=9012  窗口=True   engine.dll=未加载
  Titanfall2.exe pid=10344 窗口=True  engine.dll=0x7FF6A1C40000
结论：引擎宿主是 Titanfall2.exe → 填 auto 就行，不用写启动器名字。
```
```
另一种输出：
  Game.exe  pid=6120  窗口=True  engine.dll=0x7FF6A1C40000   ← 壳把引擎装在自己里面
结论：填 Game.exe。
```

**常见填错**：把启动器名字填进去，但引擎在子进程 → 自检会说
`自检：进程名填错了 —— 你填的 开始游戏.exe 确实有进程（pid …），但引擎不在它里面；引擎在 Titanfall2.exe（pid …）`。

## 情况二：整个目录被复制成「副本」

**典型现象**：`Titanfall2 - 副本.exe`、`Titanfall2(1).exe`、`Titanfall2 (2).exe`；
或者两份安装目录 `D:\STEAM\...\Titanfall2` 和 `D:\备份\Titanfall2` 混着点。

**改法**
- 只玩一份 → 把「进程 / 默认模块名」填**那一份的真实 exe 名**（例如 `Titanfall2 - 副本.exe`）；
- 名字里的空格、括号（全角/半角）、`-` 都要照抄。Windows 允许的字符（空格、括号、中文）插件都支持，
  唯一要求是**字符串完全相等**；
- 两份同时开着 → 会命中两个同名/不同名进程，插件按「有窗口优先」挑一个；想确定用哪一份，
  关掉另一份，或者把名字写死（写死只对**名字不同**的副本有效，同一个名字写死也分不出来）。

**例子**
```
原始：D:\STEAM\steamapps\common\Titanfall2\Titanfall2.exe        → auto 命中
副本：D:\备份\Titanfall2\Titanfall2 - 副本.exe                    → auto 不命中（名字变了）
      → 「进程 / 默认模块名」填：Titanfall2 - 副本.exe
      → 提示里会显示「名字中间有空格，前后别多打」
```

**验证**：状态卡变成 `数据源定位：Titanfall2 - 副本.exe (PID 12345) / engine.dll=0x…`。

## 情况三：被杀软隔离/恢复后加后缀

**典型现象**：昨天还好，今天游戏目录里的 exe 变成 `Titanfall2.exe.bak`、`Titanfall2.exe.quarantine`，
或者杀软把它恢复成了别的名字；甚至 exe 直接消失、双击没反应。
（破解补丁被 Defender/火绒/360 处理是常态，本插件不评判来源，只说技术上怎么处理。）

**分两种结果**

| 结果 | 处理 |
|---|---|
| exe 只是**改名**（还在原目录、能双击运行） | 填改名后的真实名；然后**把游戏目录和 DGHub 加入杀软白名单**，否则下次扫描还会改名/删除 |
| exe 被**隔离/删除** | 先从杀软隔离区恢复，再把它改回原名（或填恢复后的名字），并加白名单。否则每次启动名字都可能变，插件要跟着改，很烦 |

**例子**
```
杀软把 exe 隔离 → 你从隔离区恢复，文件成了 Titanfall2.exe.bak（Windows 不给 .bak 直接双击运行）
→ 改回 Titanfall2.exe（最省事：auto 直接命中，以后不用再管）
另一种：恢复成 TF2_restored.exe 且能运行
→ 「进程 / 默认模块名」填 TF2_restored.exe
```
**注意**：如果杀软**实时保护**会拦 DGHub 读进程内存（插件是只读、不注入，但仍可能被行为检测），
你会在日志里看到间歇性 `OpenProcess 失败（err=5）` 或 `字段 health 读取失败`，时好时坏。
这种情况光改名没用，必须给 `DGLab-Console.exe` 加白名单。

## 情况四：打包壳/整合包自己的名字

**典型现象**：进程名是 `game.exe`、`Game_packed.exe`、`launcher.exe`、`启动器.exe` 这种通用名，
看着跟《泰坦陨落 2》毫无关系。

**分两种**

| 结构 | 判断 | 改法 |
|---|---|---|
| 壳把引擎装进自己进程（常见于程序打包器） | 该进程 `engine.dll=0x…` | 填壳的名字（`Game.exe`）—— 能连上、能读，但**若壳同时改了指针布局，偏移照样要重新标定** |
| 壳把 DLL 藏进虚拟文件系统 | 该进程**没有** `engine.dll`，但磁盘上 `<游戏目录>\bin\x64_retail\engine.dll` 明明存在 | **填什么都没用**：模块表里没有它，指针链无从计算。这是加壳/虚拟文件系统的硬伤，见《进程问题速查》第 3 条 |

**例子**
```
输出：
  Game.exe  pid=4477  窗口=True  engine.dll=未加载
  （磁盘上 bin\x64_retail\engine.dll 存在）
→ 结论：壳把 DLL 藏起来了。改「进程 / 默认模块名」不会生效，需要换未加壳的版本。
```
```
输出：
  Game.exe  pid=4477  窗口=True  engine.dll=0x7FF7C3A10000
→ 结论：填 Game.exe，能连上。若读数仍是垃圾，那是版本/偏移问题，不是进程名问题。
```

---

## 四种情况的共同验证步骤

1. 改完看状态卡：`数据源定位：<你填的名字> (PID <pid>) / engine.dll=0x…`
   - 有名字没 PID → 名字还是不对（再跑 `probe_process.py` 对照）；
   - 有 PID 但 `engine.dll=未找到` → 不是名字问题了（进第 3 条/加壳）。
2. 看日志有没有新的 `自检：…`；改对了它就不再出现，恢复读取时还会补一句
   `进程自检：读取已恢复`。
3. 切一次启动方式（Northstar ↔ 官服）再确认一遍 —— 如果换了方式又读不到，说明你填的是**具体名字**、
   而这次宿主换了人；那种情况填 `auto` 最省心。

## 一张速查

| 现象 | 改哪里 | 值 |
|---|---|---|
| 目录里只有第三方启动器 | 进程 / 默认模块名 | 引擎宿主名（不一定是启动器） |
| `Titanfall2 - 副本.exe` | 同上 | 照抄带空格的全名 |
| 杀软改名/加后缀 | 同上 + 杀软白名单 | 改名后的全名，或改回原名 |
| 壳/整合包自己的名字 | 同上 | 壳名（引擎在壳里时）；引擎不在壳里则无解 |
| 全角字母、看不见的首尾空格 | 同上 | 照抄自检/探测输出里给出的名字 |
