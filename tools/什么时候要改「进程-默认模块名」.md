# 什么改动会让「进程 / 默认模块名」需要跟着改

对象：`ttf2_coyote`（泰坦陨落 2 × 郊狼插件）v2.19.0
实测环境：`D:\STEAM\steamapps\common\Titanfall2`（Steam 版 + Northstar 1.18，三套 profile）

## 一、这个字段到底管什么

它只决定两件事，别的都不管：

1. **附加到哪个进程** —— 候选名单命中哪个就附加哪个（`source.py` 的 `_ensure_open`）；
2. **纯偏移链的默认基址模块** —— 指针链里没写模块名时，基址用「宿主 exe 的主模块」（`_module_base(None)` → `_proc_name`）。

引擎 dll 本体在 `bin\x64_retail\`：`engine.dll` 9.39 MB、`client.dll` 12.96 MB、`tier0.dll`、`vstdlib.dll`…；
指针链里的 `engine.dll+111E1E68` 就是相对这个 `engine.dll`。

## 二、你这台机器上的实测事实（谁在承载引擎）

同一个安装，两条启动路径的**宿主进程名不同**：

| 启动方式 | 宿主进程 | 证据 |
|---|---|---|
| 双击 `NorthstarLauncher.exe -profile=R2Northstar` | **`NorthstarLauncher.exe`**（pid 5180） | `IGO_NorthstarLauncher_5180.log` 里 `engine.dll=0x7FFF92E50000`、`client.dll`、`server.dll`、`tier0.dll` 全在；同期**没有** `IGO_Titanfall2_*.log` |
| `-profile=R2Titanfall -vanilla`（官服） | **`NorthstarLauncher.exe`**（pid 192） | `IGO_NorthstarLauncher_192.log` 同样含 `engine.dll`/`client.dll`/`server.dll` |
| 官服直启 / Steam 按钮（vanilla） | **`Titanfall2.exe`**（pid 30668） | `IGO_Titanfall2_30668.log` 含 `engine.dll`/`client.dll`/`server.dll` |
| 直启 `Titanfall2.exe` 但卡在 EA 授权 | `Titanfall2.exe`（pid 22388）**但没加载引擎** | `IGO_Titanfall2_22388.log` 里没有任何 engine/client/server 模块记录 |

最后一行是个容易被忽略的陷阱：**进程存在 ≠ 引擎在里面**。

## 三、必须改这个字段的情况

| # | 发生了什么改动 | 为什么必须改 | 改成什么 |
|---|---|---|---|
| 1 | 游戏 exe **被改名/复制**（`Titanfall2 - 副本.exe`、整合包自带的新名字、从别的目录拷来的副本） | auto 的三个候选名全都对不上，插件报「未找到游戏进程」 | 手填改后的真实 exe 名 |
| 2 | 装的是**别的发行版/试玩版以外的名字**（如私服整合包自带的 `TF2_CN.exe`） | 同上 | 手填该名字 |
| 3 | 用**包装/兼容层**启动（第三方启动器、沙盒、虚拟机直通）导致宿主 exe 名变了 | 引擎跑在包装器命名的新进程里 | 手填包装后的名字 |
| 4 | **指针链写成纯偏移**（`0x1234 -> 0x18`，链里没有模块名） | 基址 = 宿主 exe 主模块 → 换启动方式基址就变，偏移全部作废 | 换了启动方式就同步改字段；或给链补上 `engine.dll+` 前缀（治本） |
| 5 | 上次手填了具体名字（比如为了某次调试写了 `Titanfall2.exe`），之后换到**家族之外**的宿主 | 只有泰坦陨落 2 家族内部才有互补回退 | 改回 `auto` |

## 四、不用改的情况（看着像要改，其实不该动）

| 情况 | 为什么不用改 |
|---|---|
| Northstar ↔ 官服来回切（宿主 `NorthstarLauncher.exe` ↔ `Titanfall2.exe`） | 两个名字都在 auto 候选里；且链是 `engine.dll+偏移`，两个宿主里 `engine.dll` 都加载了，基址自动对 |
| 换 profile（`R2Northstar` / `R2Titanfall` / `R2vanilla`） | 宿主都是 `NorthstarLauncher.exe`（实测见上表） |
| 用 Steam 按钮还是双击 bat 还是 EA app 启动 | 宿主名不变，只是启动链不同（那条链慢，但不是本字段的事） |
| 玩试玩版 `Titanfall2_trial.exe` | 已在 auto 候选里 |
| 游戏更新（引擎 dll 版本变了） | 宿主名没变；变的是**偏移**，要改的是 `off_health` 等链里的偏移，不是这个字段 |

## 五、改了也没用的情况（说明问题不在这个字段）

| 报错/现象 | 真正该改的东西 |
|---|---|
| `找不到模块 engine.dll —— 指针链里写的模块名必须真的加载在当前进程里` | 链里的**模块名**（或游戏更新后引擎 dll 改名） |
| 能附加但读数全是垃圾（负数、超大值） | 链里的**偏移**（`off_health` / `off_max_health` / `off_doomed` / `off_m25`） |
| `OpenProcess 失败（err=…）` | 权限：以管理员身份运行 DGHub |
| `数据源 未连接进程 ｜ 游戏进程可能已关闭` | 游戏真的没开 / 刚重启过，等它起完 |
| 宿主存在但引擎没加载（`Titanfall2.exe` 卡在 EA 授权那一步） | 不是本字段；等授权完成或换 Northstar 启动 |
| 报 `连续读到无效数据`，且当前开的是**专用服务器**（`r2ds.bat` → `NorthstarLauncher.exe -dedicated`） | 专用服务器没有客户端血量，任何进程名都读不到 |

## 六、本字段解决不了的情况

| 情况 | 原因 |
|---|---|
| 同名多开两份客户端（Northstar `-multiple`） | 名字相同；插件只能按「有可见窗口优先」挑一个，无法指定第二份。要么关掉多余那份，要么给插件加 PID 指定功能 |
| 同时开专用服务器 + 客户端 | 靠「有窗口优先」通常能选对客户端；若两者都无窗口（最小化？）可能挑错 |
| 游戏跑在别的进程宿主里（某些兼容层把游戏并进自己的进程） | 引擎不在你期望的 exe 里，得按实际宿主名填 |

## 七、一条命令自检

**插件自己也会查**（v2.20.0 起）：读取失败时它会把上面这些情况判一遍，直接往日志里打一条「自检：…」，
里面带你当前的配置值、探测到的进程明细（名字 / pid / 有无窗口 / engine.dll 地址）和建议改成什么。
每 30 秒最多一条，结论不变就 5 分钟后再说；读取恢复时补一句「进程自检：读取已恢复」。

想手动查或者想在游戏外先看一眼，游戏运行时在插件目录下执行：

```pwsh
python tools\probe_process.py
```

它会枚举所有名字里含 `titanfall` / `northstar` 的进程，逐个报告
「有没有窗口 / 有没有加载 `engine.dll`（及 `client.dll`、`server.dll`）/ 基址」，
最后直接告诉你该填什么：

```
  引擎宿主进程：Titanfall2.exe（pid 30668）
  → 「进程 / 默认模块名」填：Titanfall2.exe
  → 这个名字在 auto 候选里，直接填 auto 也能连上；
    把名字写死的好处是：同时开了别的候选进程时不会被抢走。
```

## 八、当前配置的结论

`D:\dghub\config.json` 里本插件段现在是：

```
mem_module   = auto
source_mode  = memory
off_health     = engine.dll+111E1E68
off_max_health = engine.dll+111E1E6C
off_doomed     = engine.dll+111E20C4
off_in_titan   = engine.dll+111E1D0C
off_m25        = engine.dll+111E0F88
```

五条链**全部自带 `engine.dll`** 模块名，所以：

> 在你这台机器现在的配置下，Northstar ↔ 官服 ↔ 任意 profile 互切，**都不需要动「进程 / 默认模块名」**。
> 只有出现第三节那五种情况（改名副本、包装器、纯偏移链、手填残留、家族外宿主）才需要改。
