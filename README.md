# 泰坦陨落 2 联动（ttf2_coyote）v2.20.5

DGHub 外部插件（SDK v1）：把《泰坦陨落 2》泰坦血量的**数值变化**映射为郊狼电刺激。
数据源是**进程内存只读轮询**——不注入、不写游戏内存、**不读屏**。

介绍页（GitHub Pages）：<https://galactic-reformer.github.io/ttf2_coyote/>　｜　
安装包：[Releases](https://github.com/galactiC-reformeR/ttf2_coyote/releases)　｜　
本仓库目录结构见文末「[仓库结构](#仓库结构)」。

## 通道分工

| 条目 | 默认通道 | 形态 | 默认强度（郊狼值） |
|---|---|---|---|
| **A** 血量档位 | A | 电平，档位变了才改 | 70%→20 / 50%→30 / 30%→40 / 濒死→60 |
| **B** 单次受击 | B | 单次脉冲（可开关） | 25 |
| **E** 死亡脉冲 | B | 死亡界面出现后持续（默认 5 秒，`☠️ [E]` 段可调 0.5–15 秒）；波形默认**留空 = 恒定**，也可自选 | 45 |

处决动画期间**不静音**：保持濒死档持续输出（`A_DOOM`），受击脉冲照常；死亡脉冲（E）不受影响。

### 受击脉冲的触发门槛（v2.13.0 起）

不是每次掉血都发脉冲 —— 满足**任一条**才触发：

| 规则 | 配置项 | 默认 |
|---|---|---|
| 单次掉血 ≥ N | `⚡ [B] → 单次受击触发阈值` | **1500** |
| 最近窗口内累计掉血 ≥ M | `⚡ [B] → 1 秒内累计伤害阈值` + `累计窗口 (ms)` | **2000 / 1000ms** |

两条都填 **0** 就恢复旧行为（任何掉血都算一次受击）。

这条规则用来过滤散弹弹丸、DoT、环境伤害这类小额掉血；泰坦武器一次 200~500、核心技能上千，靠"累计"那条也能覆盖连打。
另外注意**频率上限 = max(受击时长, 不应期)**（默认 `max(300, 200) = 300ms`，约 3.3 次/秒）：脉冲在途或不应期内的掉血会合并成一次（日志里 `pulse-end n=3 dt=450` 就是合并结果）。想把体感频率再降，就调大「受击时长」。

## 通道分配：一条通道同时只有一种输出

上面三个条目按**输出形态**分成两组，各占一条物理通道：

- **持续输出**（条目 A，电平式）→ 配置 `🎯 [A] → 输出通道（持续）`，默认 **A 通道**
- **脉冲输出**（条目 B 受击、条目 E 死亡脉冲）→ 配置 `⚡ [B] → 输出通道（受击）`、`☠️ [E] → 输出通道（死亡脉冲）`，默认 **B 通道**

**规则**：两组不能压在同一条通道上 —— 它们都用 `set_strength` 操作同一条强度层，压在一起会互相覆盖（档位强度和受击脉冲互相打断）。所以：

- 受击/死亡脉冲**不得**占用持续输出那条通道；`E` 可以和 `B` 共用一条（两者不会同时发生）；
- 如果你把脉冲选到了持续通道上，插件按**持续输出优先**处理：脉冲自动改用另一条通道，并把界面上的值**改回实际值**（同时打一条 warning 日志说明原因）；
- 界面下拉只有「A 通道 / B 通道」两项：旧版的「两个通道（both）」与互斥规则冲突，已移除；
- **改通道即时生效**：插件先把两条通道归零，再按新映射重新下发，不会把上一次的档位强度留在被释放的通道上。

> DGHub 的 `config_schema` 不支持字段联动（没法在界面上直接禁用冲突选项），所以互斥由插件自己强制 + 写回界面值。


## 安装

仓库根目录就是插件本体（`main.py` 在这一层），所以插件目录名要叫 `ttf2_coyote`：

```pwsh
# 直接克隆到插件目录（目录名必须与插件 id 一致）
git clone https://github.com/galactiC-reformeR/ttf2_coyote.git D:\dghub\plugins\ttf2_coyote
# 或者下 Releases 里的 zip，解压出 ttf2_coyote 目录放到 D:\dghub\plugins\
```

1. 确认目录里能看到 `main.py` / `manifest.json`（不是套了一层同名目录）；
2. DGHub → 设置 → 外部插件 → 扫描/刷新 → 打开「泰坦陨落2 联动」；
3. 插件进程由 DGHub 以 `DGLab-Console.exe --plugin-runner main.py` 启动，无需自行安装 Python。

更新版本时在该目录 `git pull` 即可（配置文件在 DGHub 那边，不会被覆盖）。

## 进程 / 默认模块名

`⚙️ 基础与数据源 → 进程 / 默认模块名` 填什么，插件就附加哪个进程：

- `auto`（默认）= 依次尝试 `Titanfall2.exe` → `NorthstarLauncher.exe` → `Titanfall2_trial.exe`；
- 填具体名字，则先认这个名字；只有名字属于泰坦陨落 2 家族时才补上另外两个同族候选；
- 找到进程后「默认模块名」就是该进程的主模块；指针链自带模块名（`engine.dll+0x1234`、`"某某.exe"+偏移`）时以链里写的为准；
- **模块名允许带空格**（nw.js 打包的游戏常有，如 `"Die cry.exe"+0x1234`）；
- **同名多进程**（nw.js / Electron 会开出 8 个同名进程）时优先选有可见窗口的那个，都没有窗口才退回 pid 最小的。

> 附到别的游戏只解决「能连上」：指针链里的偏移仍是泰坦陨落 2 的，换游戏必须换链，否则读到的是 PE 头/常量区，
> 引擎会判成垃圾读数并 fail-closed。RPG Maker MV/MZ（nw.js）这类游戏血量在 JS 里，**静态指针链读不到**，
> 要改用 CDP 或桥接插件 —— 完整实测过程见 [`tools-mz/接入Die cry-修改方法.md`](tools-mz/接入Die%20cry-修改方法.md)。
>
> 什么时候**必须**改这个字段（改名副本、包装器启动、纯偏移链…）什么时候不用改（Northstar ↔ 官服互切、
> 换 profile、游戏更新），以及改错方向会浪费时间的误判清单，见
> [`tools/什么时候要改「进程-默认模块名」.md`](tools/什么时候要改「进程-默认模块名」.md)；
> 游戏运行时执行 `python tools\probe_process.py` 会直接打印该填什么。

### 进程自检（v2.20.0 起）

读不到数据时插件会自己查一遍进程，把「为什么读不到、该把进程名改成什么」直接写进日志，不用去猜：

- **查什么**：枚举所有名字含 `titanfall` / `northstar` 的进程（改名副本也能认出来），逐个看有没有可见窗口、
  有没有加载 `engine.dll`（引擎宿主才加载它）；
- **判什么**：没启动 / 进程在但引擎没加载（卡在 EA 授权、或开的是 `-dedicated` 专用服务器）/
  引擎在别的进程里（附错进程）/ 你填的名字根本不存在 / 名字填对了但权限或偏移有问题 —— 六种情况分别给不同措辞；
- **报什么**：一条 `warning`（少数情况 `error`）日志，含探测明细 `名字(pid,有无窗口,engine.dll 地址)` 与明确建议
  （例如「请改成 NorthstarLauncher.exe」「auto 候选里就有它，读不到是权限/偏移问题」）；
- **不刷屏**：每 30 秒最多查一次；结论没变就只在 5 分钟后再念一遍；读取恢复时补一句「进程自检：读取已恢复」；
- **不拖慢采样**：只在读取失败时触发，不在 8ms 热路径上。

用例：`python tests\test_selfcheck.py`（13 种情况逐条断言，不需真游戏）；
集成行为在 `python tests\test_session.py` 的「进程自检」用例里。
常见进程问题的完整对照表（症状 → 原因 → 改法）见 [`tools/进程问题速查.md`](tools/进程问题速查.md)；
「名字不对」这一类（启动器替换 / 副本改名 / 杀软加后缀 / 壳的名字）的逐例详解见
[`tools/名字不对-改法详解.md`](tools/名字不对-改法详解.md)。

## 第一步：用模拟数据确认链路（不需要游戏）

配置页「基础与数据源」→ **数据源 = 模拟数据** → 选剧本 → 打开「输出变更日志」。
插件把剧本按**真实时间轴**回放（剧本里的 tick 就是真实毫秒）。

### 默认剧本 R1：一次完整演练（只跑一次）

`R1` 是默认剧本，专门用来快速核对"两个通道在两个档位上分别输出什么"，**播完就停、不循环**：

```
现在处于模拟状态，R1，以下为模拟运行产生的日志。        ← 开场白
[0.0] hp=3700/12500 doomed=0 titan=1 alive=1 | ch=a slot=A_30 cfg=40 eff=40 clamp=- reason=init
[0.3] hp=3650/12500 doomed=0 titan=1 alive=1 | ch=b slot=B_HIT cfg=25 eff=25 clamp=- reason=hit
[0.6] hp=3650/12500 doomed=0 titan=1 alive=1 | ch=b slot=B_NONE cfg=0 eff=0 clamp=- reason=pulse-end n=1 dt=50
插入电池，泰坦生命值恢复                              ← 剧本里夹的提示行
[1.4] hp=6200/12500 doomed=0 titan=1 alive=1 | ch=a slot=A_50 cfg=30 eff=30 clamp=- reason=recover-refresh
[1.7] hp=6150/12500 doomed=0 titan=1 alive=1 | ch=b slot=B_HIT cfg=25 eff=25 clamp=- reason=hit
[2.0] hp=6150/12500 doomed=0 titan=1 alive=1 | ch=b slot=B_NONE cfg=0 eff=0 clamp=- reason=pulse-end n=1 dt=50
此次模拟场景输出已结束                                ← 结束语；随后两通道归零并停下，不再重播
```

即：**30% 档（3700/12500）两个通道各出一次** → 提示"插入电池，泰坦生命值恢复" → **50% 档（6200/12500）
两个通道各出一次** → 结束。配合「演练模式」时每条输出前面还有一行「待下发」，把**波形名与换算后的
百分比**一并写出来：

```
[演练] 待下发：强度 A 通道 = 郊狼值 40（按上限 89 换算为 44%）
[演练] 待下发：强度 B 通道 = 郊狼值 25（按上限 89 换算为 28%）
[演练] 待下发：波形「CS2-受伤」→ B 通道
```

### 另外四个情境演练（同样是"只跑一次 + 带中文解说"）

- **S1** 档位递进 + 受击：血量从 68% 一路掉到濒死，A 通道四档 20/30/40/60 依次切一遍，每次掉血给一次 B 脉冲
- **S2** 被处决 → 死亡界面 → 死亡脉冲：处决动画期间保持濒死档输出，死亡界面出现后给一次 45 强度、5 秒（默认时长，可调）的脉冲
- **S4** 插电池恢复：回血后按新档位重新输出，**不出**受击脉冲
- **S10** 连续受击合并：短时间内连挨几下只给一次脉冲

这四个与 R1 同一格式：**只跑一次**，每一步都配一句中文解说，播完出结束语即停。以 S1 为例：

```
现在处于模拟状态，S1，以下为模拟运行产生的日志。
① 泰坦血量 3400/5000（68%）：A 通道进入 70% 档，持续输出
[0.0] hp=3400/5000 doomed=0 titan=1 alive=1 | ch=a slot=A_70 cfg=20 eff=20 clamp=- reason=init
② 受到一次攻击：B 通道给一次受击脉冲
[0.1] hp=3000/5000 doomed=0 titan=1 alive=1 | ch=b slot=B_HIT cfg=25 eff=25 clamp=- reason=hit
③ 血量跌破 50%：A 通道切到 50% 档，同时再受击一次
[0.5] hp=2400/5000 doomed=0 titan=1 alive=1 | ch=a slot=A_50 cfg=30 eff=30 clamp=- reason=tier-enter
④ 血量跌破 30%：A 通道切到 30% 档，同时再受击一次
[0.9] hp=1450/5000 doomed=0 titan=1 alive=1 | ch=a slot=A_30 cfg=40 eff=40 clamp=- reason=tier-enter
⑤ 泰坦进入濒死：A 通道切到濒死档
[1.3] hp=0/5000 doomed=1 titan=1 alive=1 | ch=a slot=A_DOOM cfg=60 eff=60 clamp=- reason=tier-enter
此次模拟场景输出已结束
```

（`testvectors/scenarios.json` 里剩下的 12 个剧本 —— S3、S6–S9、S11–S17 —— 仍是**循环重播**，
用于反复压判定逻辑；在配置里手填 id 前缀即可，例如填 `S12`。）

**建议先开「演练模式」**（不向设备发任何输出）核对日志。演练模式下插件不会给设备发任何命令
（退出时也不发归零），但会把「本来会发的命令」写进日志，于是**波形名与换算后的百分比都能核对**：

```
[演练] 待下发：强度 A 通道 = 郊狼值 60（按上限 89 换算为 67%）
[演练] 待下发：波形「CS2-受伤」→ B 通道
```

日志本身只体现**决策**（走哪个条目、强度、时长、为什么起停），**不含波形名**——A 通道是电平式持续输出，
本来就没有"波形"；B/E 的波形名只出现在上面这种「待下发」行（或真正下发时的设备命令）里。

### 模拟运行的边界与锁定

日志按「一轮剧本 = 一次模拟」分段：开场白 → 运行日志 → 结束语。`R1` 这类**只跑一次**的剧本
（`once: true`）结束后会归零两通道并停下，**不再重复报**；其余剧本会自动进入下一轮（每轮都会复位引擎状态）。

两条约束：

- **一轮模拟结束前，改剧本 / 改数据源不生效**：改动推迟到本轮结束后生效，期间只提示一句
  `模拟运行中：模拟剧本 / 数据源的改动将在本次模拟结束后生效`；
- **通道重叠则拒绝这次模拟**：「单次受击」或「死亡脉冲」被选到「持续输出」占用的那条通道上时，
  插件只发警告并**拒绝本次模拟输出**（不读剧本、不喂引擎、不下发、不出运行日志），
  且**不替你改回界面值** —— 请自己把其中一个改到另一条通道：

```
通道重叠：单次受击、死亡脉冲 与「血量档位持续输出」指向同一条通道 —— 本次模拟输出已拒绝，请把其中一个改到另一条通道
```

> 内存模式下的重叠仍是「持续输出优先、脉冲自动让路并写回界面值」（见上一节）。模拟模式故意保留
> "照实报错、不改你的选择"的行为，方便你在正式使用前发现通道配错。

### 新剧本怎么写（`testvectors/scenarios.json`）

每个剧本 = `id` + `steps`，加两个可选字段：

- `"once": true`：只播一次，播完收尾（演练用）；
- 步骤里的 `"note_log": "文字"`：走到这个 tick 时往日志里夹一条提示行（如"插入电池…"），不改任何状态；

## 第二步：内存定位已内置（不需要填任何地址）

**配置页里已经没有「内存定位」区** —— 地址已内置在代码里，插件装上就能用，不用 Cheat Engine、
不用指针链、不用手动填偏移（这样也避免了"填错一个字符就完全没输出"这类麻烦）。

内置值（2026-10-17 私服实测有效，对应 `engine.dll` 9,843,712 字节 / SHA256 前 16 位 `58EB1A1B44B30275`）：

| 字段 | 地址 | 说明 |
|---|---|---|
| 泰坦当前血量 | `engine.dll+111E1E68` | 必需；读不到就 fail-closed 保持静默 |
| 泰坦最大血量 | `engine.dll+111E1E6C` | 必需的百分比分母 |
| 濒死标志 | `engine.dll+111E20C4` | **位域**：`bit0` = 濒死（掩码已内置为 1） |
| 是否在泰坦内 | `engine.dll+111E1D0C` | 1 = 在泰坦里 |
| 死亡界面 m25 | `engine.dll+111E0F88` | 死亡脉冲的触发信号 |
| 是否存活 / 生命周期 id | 未内置 | 用「血量 > 0」「最大值变化 + 上下机」推导，够用 |

什么时候需要动它：**只有游戏更新（`engine.dll` 变了）才需要重新定位**。两种方式：

1. 跑 `tools\calibrate.py` 得到新地址，写进 `D:\dghub\config.json` 里本插件段的同名键
   （`off_health` / `off_max_health` / `off_doomed` / `off_m25` / `off_in_titan`）—— 配置文件里的值
   **仍然优先于内置值**，所以不用改代码；
2. 或者改 `source.py` 里的 `LOCATE_DEFAULTS` 常量（发布新版本时一并更新）。

### 一条命令自动标定（`tools\calibrate.py`）

不想手动挖地址就用这个工具：它按"已知的血量形状"去反查每个字段，一次跑完标定 health / max_health / doomed（含位掩码）/ m25，并输出 `tools\calibration.json`（游戏更新后用来更新配置文件里的同名键）。

```powershell
# 0) 先自检匹配算法（不需要游戏）
python tools\calibrate.py --selftest

# 1) 实机标定：启动后按下面第 1 步的顺序在游戏控制台操作（私服可用）
python tools\calibrate.py --minutes 4

# 2) 用录下来的轨迹复算（可选）
python tools\calibrate.py --replay tools\calibration-trace.json
```

第 1 步期间在游戏控制台依次敲（每步之间停 2 秒）：

```
ns_dmg_hp <满血的 64%>      # 12500 血 → ns_dmg_hp 8000
ns_dmg_hp <满血的 48%>      # → ns_dmg_hp 6000
ns_dmg_hp <满血的 28%>      # → ns_dmg_hp 3500
ns_dmg_doom                # 进濒死（血量与最大值一起塌缩成 1/5）
ns_dmg_stop_on_doom 0
ns_dmg                     # 打爆泰坦 → 死亡界面 → 复活
ns_dmg                     # 再敲一次关掉持续伤害，别把铁驭也打死
```

（三条血量值只要构成 64% / 48% / 28% 的比值形状就行；工具按**比值**匹配，换机体不用改。）

匹配用的血量形状是 **满血 → 64% → 48% → 28% → 濒死池（1/5）→ 被毁 → 复活 → 新泰坦满血**（按比值匹配，所以 7500/10000/12500/15000/17500 都适用）。`doomed` 与 `m25` 靠**置位时刻**区分：前者在"进濒死"那一刻置位、复活时清零，后者在"泰坦被毁"那一刻置位。

标定完成后：工具的 `tools\calibration.json` 里就是 `off_health` / `off_max_health` / `off_doomed` （含 `flag_true_value` 与 `flag_mask`）/ `off_m25`，把它们写进 `D:\dghub\config.json` 本插件段的同名键即可（配置文件优先于内置值，不用改代码）。掩码是位域信息：濒死标志 `bit0 = 濒死`，所以 `flag_mask` 通常是 1。

定位方法见 `../TF2插件设计思路-v3-测量量清单.md`、`v7-条目收敛与垃圾读数详解.md`：
核心手段是**受控刺激 + 精确 Δ 匹配**（在私人服上用脚本施加已知伤害 δ，找「恰好下降 δ」的字段）。

## 内置定位的验证记录（2026-10-17）

**全部是静态地址**（在 `engine.dll` 数据段，重启游戏、换电脑都不变），因此**不需要指针链、也不需要用户填**：

| 字段 | 填什么 | 验证依据 |
|---|---|---|
| 泰坦当前血量 | `engine.dll+111E1E68` | 精确跟随伤害、换机复位 |
| 泰坦最大血量 | `engine.dll+111E1E6C` | 与血量相邻；濒死时会一起变成濒死池（2500） |
| 死亡界面 `m25` | `engine.dll+111E0F88` | **16 次铁驭阵亡全部一致**：阵亡帧 0→1、复活帧 1→0 |
| 濒死 `doomed` | `engine.dll+111E20C4` | 见下方「濒死判据」—— 这个字节是**位域**：`bit0` = 濒死（另一常驻标志占 `bit1`），必须配「标志位掩码 = 1」读 |
| 是否在泰坦内 | `engine.dll+111E1D0C` | 泰坦内=1、下机=0、泰坦被毁时归 0（三重一致） |
| 是否存活 | 留空 | 未标定时自动用「血量是否为 0」推导（泰坦被毁、铁驭阵亡都会归 0） |

标定方法不是 CE 扫描，而是**内存窗口变化抓取 + 稳态差分**（工作区 `tools/flag_watch.py`
记录"哪个字节在什么时候变了"，`tools/flag_report.py` 做稳态窗口对比与地址翻译）——
标志位只需要"某个动作让某个字节翻一次"，比找血量（要指针链）容易得多。

### 濒死判据（实测踩坑后定案）

泰坦进濒死时「**最大血量会塌缩成濒死池**」（= 机体最大的 1/5）：实测 `12500 → 2500`
（LTS 局与消耗战局各一次，两次都是 2500）。而标志位 `111E20C4` **只在"人在泰坦里时触发
濒死"那一刻为 1，下机后再上机不会恢复成 1** —— 实测玩家重新登上濒死泰坦时
`ns_dmg_status` 打印「濒死 是」但该字节是 0，导致 A 通道不发濒死档。

因此插件用**双判据（任一成立即判濒死）**：

1. 标志位 `111E20C4` 的 **bit0** 为 1（比较方式：`(值 & 标志位掩码) == (真值 & 标志位掩码)`，掩码默认 1），**且**当前血量 ≤ 最大血量 × 「濒死标志可信度门槛」（默认 25%）；
2. **最大值塌缩**：`在泰坦内 且 当前最大值 ≤ 本次驾驶峰值 / 3`，或 `在泰坦内 且 最大值 ≤ 3500`
   （五种机体真实最大血量最低 7500，濒死池最大 3500，所以这个量级只可能是濒死池；
   这条同时覆盖"插件启动时人已经在濒死泰坦里"）。

会话测试 `tests/test_session.py::case_doomed_derivation` 守着这套判据（含恢复、换机体、
峰值未建立三种边界）。

> **这个字节是位域，不是布尔**（2026-10-17 私服标定，用 `ns_dmg_doom` 精确造濒死）：
> 同一局里两台泰坦分别实测到 **正常 `2` → 濒死 `3`** 和 **正常 `0` → 濒死 `1`**，
> 即 **`bit0` = 濒死**，`bit1`（值 2）是另一个常驻标志。所以读法必须是
> `(值 & 掩码) == (真值 & 掩码)`（掩码默认 **1**）。按旧的"整字节 == 1"比较会两头出错：
> * `bit1=1` 的泰坦上濒死值变成 `3` → `3 == 1` 为假 → **濒死档永远发不出来**（70/50/30 之后直接没有濒死）；
> * `bit1` 从 `2` 翻成 `1` 的瞬间整字节恰好 `== 1` → **在高血量（如 62%）上误判濒死**，A 通道直接跳到濒死档。
>
> 掩码填 **255** 可退回旧行为（整字节比较）；`flag_true_value` 仍是"真值"（默认 1）。
>
> **另外还有一道血量门槛**（默认 25%）：即使标志位判定成立，也要求当前血量 ≤ 最大血量 × 25% 才采信
> —— 真濒死时血量必然 ≤ 濒死池（最大值的 1/5 = 20%），所以这道门槛只挡误判、不会漏报。
> 门槛取值：**25 = 默认**；**100 = 永远采信**；**0 = 完全不用标志**（只靠最大值塌缩）。
> `case_doomed_flag_gate`（门槛）与 `case_flag_mask`（位掩码）守着这两条。

### 两个必须知道的读法陷阱（都已处理）

1. **这些标志位常常是"状态枚举"而不是布尔**：`111E20C4` 在濒死时是 `1`，泰坦被摧毁后变成
   `4/5`。所以插件按「**与期望值相等**」判读（`标志位「真」值`，默认 1），而不是「非 0 即真」
   —— 否则"泰坦已被摧毁"会被误判成"濒死"。
2. **泰坦被毁那一帧，死亡界面标志会瞬时抖动约 0.3 秒**（实测）：不去抖会误发一次 5 秒死亡
   脉冲。插件内置固定 **500ms** 去抖挡掉（`main.py` 的 `M25_MIN_HOLD_MS`，不做成面板项）；
   真实死亡界面持续 8.6 秒，很安全。
   黄金场景 `S14` 专门守着这条（抖动 300ms 全程不得出现死亡脉冲）。
3. **上下机与进濒死会让血量/最大值同步跳变**（12500→100、12500→2500、100→25）：早先
   「同一纪元内变化幅度超过最大血量即判垃圾读数」的守卫会把这些**合法切换**全毙掉，导致
   A 通道被 fail-closed 整段关闭（濒死档 60 发不出来）。现在「最大血量变了」或「上下机
   切换了」视为测的对象换了，放行并静默重基线；真正的垃圾读数（负血量、超范围、读失败）
   照旧 fail-closed。黄金场景 `S16` 守着这条。

**死亡脉冲的触发条件**：按最初需求 —— **任何死亡界面出现都发**（含步行当铁驭被打死），
不再要求"死亡瞬间在泰坦内"（黄金场景 `S15` 守着这条）。

### 端到端验收（2026-09-19 实测，郊狼已连、体感确认）

- 濒死泰坦内 → `ch=a slot=A_DOOM cfg=60 eff=60` → **体感：A 通道 60 持续输出** ✓
- 铁驭阵亡 → `ch=b slot=E_DEATH cfg=45 eff=45 reason=death-screen` → 5 秒后
  `reason=pulse-end dur=5000` → **体感：一次 45、持续 5 秒（默认时长）的脉冲** ✓
- 修复后日志中不再出现 `连续读到无效数据` ✓

## 郊狼重连后的自动恢复

**故障现象**：郊狼断开再连上后，插件不再有任何输出，必须把插件关掉再打开才恢复。

**真实原因**（实测，不是猜的）：插件按 `(档位, 强度)` 去重下发，设备断开期间强度层的实际值
已经归零，但插件缓存的"上次下发值"没变 → **从此再也不发**。DGHub 只在插件注册时推一次
`device_info`，之后设备状态变化不通知插件，所以插件也感知不到。

**处理方式**：插件按 `🔧 维护 → 定期重发间隔 (秒)`（默认 3 秒）**幂等地重发当前输出**
（清掉下发缓存 + 让引擎重新下发一次）。设备重连后最迟一个周期内自动恢复；受击脉冲／
死亡脉冲在途时自动延后，不会打断脉冲；值没变化时设备侧完全无感知。填 `0` 关闭。
输出没恢复时可以手动选 `🔧 维护 → 立即重发当前输出 → 立即重发一次`。

> ⚠️ **绝不要用"插件自己断开再重连"来实现自愈**（早期版本犯过这个错）：DGHub 在插件自行
> 断开后仍认为该插件有活跃连接，会一直拒绝重新注册（宿主日志 `远程插件 ttf2_coyote 已有
> 活跃连接，拒绝重复注册`），插件就此永久失去输出能力，只能靠你在 GUI 里关开插件救回来。
> 因此插件只在**连接真的断了**（宿主关闭、收发异常）时才重新注册。

顺带说明：日志里 `设备目标不可用，命令已丢弃: device target is unavailable: <id>` **不是错误**，
它只表示那一刻郊狼没连上（该 id 是 `config.json` 里的全局目标，不随连接变化）。

## 强度换算与郊狼上限

换算公式是 `pct = 郊狼值 × 100 ÷ 该通道上限`，所以**上限取错会让所有强度按比例偏移**。
上限**不可配置**（避免"填错导致整体强度减半/翻倍"），只有两个来源：

1. **设备上报**（`device_info.max_strength_a/b`）—— 最准。注意 DGHub **只在插件注册那一刻上报**，
   那次上报失败（实测日志 `V4 initial device snapshot failed`）插件就永远拿不到；
2. 上报缺失时**按固定 100 换算** —— 与郊狼 V3 的实际上限一致。

> **实测过的坑**：上限取 200 时，配置的郊狼值 63 会被算成 `63 × 100 ÷ 200 = 32%`，
> 也就是**所有强度都只有一半**（濒死档最明显）。所以默认值定为 100，且从配置页移除。
> 如果你的设备上限其实是 200，请在**郊狼已连接的状态下启用插件**，让 DGHub 把真实上限报上来。

## 日志格式

变更日志按 `(slot, cfg, eff, clamp, reason)` 变化时输出一行，`cfg` 与 `eff` 并列：

- **cfg** = 你在条目里配的强度；**eff** = 实际下发的强度；两者不等时 `clamp` 会说明被谁削顶；
- `reason` 解释每条 0 输出（`anim-mute` / `switch-off` / `death-window` / `invalid` …）；
- 排查「体感与配置不符」时，第一眼看 `cfg` 与 `eff` 是否相等。

行首还带三个诊断字段，专门用来查「为什么这个血量会判濒死」：

```
[12.3] hp=7800/12500 doomed=0 peak=12500 titan=1 alive=1 | ch=a slot=A_70 cfg=20 eff=20 clamp=- reason=tier-enter
[13.1] hp=2400/12500 doomed=1(collapse) peak=12500 titan=1 alive=1 | ch=a slot=A_DOOM cfg=60 ...
[14.0] hp=2500/2500  doomed=1(flag)     peak=2500  titan=1 alive=1 | ch=a slot=A_DOOM cfg=60 ...
```

- `doomed=1(flag)` = 濒死由**标志位**判定；`doomed=1(collapse)` = 由**最大值塌缩**判定；`flag+collapse` = 两者都成立
- `peak` = 本次驾驶记录到的**最大血量峰值**。若它明显大于机体真实最大血量（如 >17500），说明被垃圾读数污染过 ——
  插件现在会用「最大血量合理上限」（默认 20000）挡住这种读数，并打一条 `最大血量读数异常…` 的 warning

## 安全

| 机制 | 说明 |
|---|---|
| 只读内存 | 仅 `PROCESS_VM_READ`，绝不写游戏内存 |
| 急停热键 | 默认 `F12`（可改），按下两通道立即归零，再按恢复 |
| 插件自身上限 | 默认 80（郊狼值），任何条目都不会超过它 |
| 失联归零 | 数据源失联超过 3 秒自动切断两通道 |
| 退出归零 | 插件停止/断开时两通道归零 |
| fail-closed | 读到无效数据时**不产生任何脉冲**（宁可漏报，绝不误报） |

## 排查「没有任何输出」

按顺序看日志，基本一眼能定位：

| 日志里的迹象 | 原因 | 怎么办 |
|---|---|---|
| `演练模式已开启：只把「待下发」写进日志，不向设备发送任何命令`，且每行输出都带 `[演练] 待下发` | **演练模式还开着** —— 插件一个包都不发 | 配置里关掉「演练模式」（关掉时会有一条 `演练模式已关闭：输出将真实下发给设备`） |
| `数据源：模拟数据源：…` | 数据源还是模拟剧本，压根不读游戏 | 数据源切成「内存只读轮询」 |
| `内存字段未标定：插件不会输出任何刺激` | 内置定位读不到（游戏更新过？） | 跑 `tools\calibrate.py` 重新定位 |
| 满屏 `reason=invalid` / `连续读到无效数据…` | 读数被判无效 | 见「排查『连续读到无效数据』」一节 |
| 有 `slot=A_NONE … reason=no-titan` 或 `reason=idle` | **这是正常的没有输出**：不在泰坦里，或血量在最高档之上 | 坐进泰坦、把血打下去再看 |
| **输出强度只有配置的一半**（如濒死档配 63 却只感觉到约 32） | 郊狼上限没上报成功，插件退回**旧的 200 换算**（`pct = 63 × 100 ÷ 200 = 32`）。实测日志里出现过 `V4 initial device snapshot failed` 就是这种情形 | 升级到 v2.17.0+（上限锁死为 100）；若设备上限确实是 200，在郊狼已连接时重新启用插件 |
| `设备未连接：DGHub 会丢弃所有输出命令` | 郊狼没连上，或没在插件上重新选输出目标 | 连好郊狼；必要时重选目标（DGHub 只在插件启动那一刻上报设备上限） |

两点补充：

- 演练模式下**不会**做「定期重发」（没有设备侧强度层可丢），所以同一档位的 `[演练] 待下发` 只出现一次；
  如果你看到它每 3 秒重复，说明那是旧版本。
- 演练剧本是 `once`：播完出 `演练已完成：可切换剧本/数据源重新开始，或点「🔧 维护 → 重播当前演练 → 立即重播」`，
  之后**不再有运行日志**（这是"不重复报"），但状态卡会一直显示「演练已完成」保持心跳；要再放一遍用维护里的重播项。

## 排查「连续读到无效数据」

这条提示在**连续 5 帧读数被判无效**时触发（每 30 秒最多一条）；读数**恢复稳定 3 秒后提示自动撤销**。
被判无效的情形有四种：读取失败、最大血量 ≤ 0、血量超范围（负值或大于最大值）、同纪元内单次变化超过最大血量。
插件会把**是哪一条挂了、读的是哪个进程、最近一帧长什么样**一并写进这条日志，照下面分档处理：

| 日志里的原因 | 通常是什么 | 怎么办 |
|---|---|---|
| `最大血量<=0（字段没读到泰坦量级）` | 不在对局里 / 主菜单 / 没坐进泰坦（此时本来就没有可输出的档位，属正常）；也可能是最大血量字段失效 | 先进对局坐进泰坦再看；一直在泰坦里仍为 0 → 按 `CE标定清单.md` 重新标定 |
| `血量超范围（… 不在 0..max）`、`同纪元内单次变化超过最大血量` | 地址错位：引擎构建变了，或地址指到了别的字段 | 重新标定（换引擎版本 / 换启动方式后必然要重做） |
| `读取失败` | 游戏进程已关闭，或句柄 / 模块基址失效（切官服、重启游戏后） | 重启插件；仍不行说明进程或模块解析不对 |

要**当场定性**，在游戏运行时用只读探针直接读那两个地址，再与游戏内 `ns_dmg_status` 对照
（本仓库 `tools\check_addrs.py`）：

```pwsh
python tools\check_addrs.py engine.dll+111E1E68 engine.dll+111E1E6C
```

探针只读、不写游戏内存。它打印的 int32 应该等于 `ns_dmg_status` 显示的「泰坦血量 / 最大血量」；
如果探针读到的是正常值而插件读到 0，问题在插件的进程 / 模块解析，不在地址本身。

## 已知限制

1. **用户自设的设备上限插件读不到**：SDK 只提供设备最大强度（`device_info.max_strength_*`），
   因此插件保证「不超过自身配置值与设备最大强度」，但**无法显示是否被用户上限削顶**；
2. **A 通道是恒强度的电平输出**（档位变了才改强度，波形由主程序强度层默认波形决定）：
   条目里没有「波形」可选，「波形」只属于 B / E 的脉冲输出。原先那两个「档位切换时播一次波形 /
   档位切换波形」面板项从来没被插件读取过（默认关闭且无实现），v2.20.1 已删除；
3. 为实现「立刻切断通道 B」的要求，脉冲使用 `set_strength` 而非 `trigger` 的 rollback 租约，
   因此**不参与**主程序的「高强度事件音效」判断；
4. **处决动画不静音**：处决期间保持濒死档持续输出（按需求），所以原 `m20` 字段已移除；
   `doomed` / `m25` / `in_titan` 已标定并验证，濒死档（60）与死亡脉冲（45 强度 × 默认 5 秒、时长可调）均已可用。

5. **通道互斥做不到界面级拦截**：SDK 的 `config_schema` 没有字段联动，「输出通道（受击）」
   下拉里仍会列出持续输出占用的那条通道。选了它不会出错，但会被插件自动让路并把界面值改回
   实际值（日志里有一条 `通道分配：…` 的 warning）。

## 声明

- 只读游戏内存（`PROCESS_VM_READ`），不注入、不写游戏内存、不读屏，也不做任何影响对局的输入。
- 强度只负责下发与归零；实际体感请从低档试起，并记住急停手段（急停热键、退出归零、失联 3 秒归零）。
- 在官方服务器上使用第三方插件可能违反游戏服务条款，风险自负。
- 面向成年用户自用，请遵守所在地法律法规与设备厂商说明。

## 反馈

报问题前先过一遍 [SUPPORT.md](SUPPORT.md) 的三步自查。还是要报的话，请附上：
日志里从「连接 DGHub」到出错的那几行、游戏进程名、以及 `python tools\probe_process.py` 的输出 ——
这三样基本就能定位到「进程不对 / 偏移失效 / 配置冲突」。

- Bug 与功能建议：[新建 issue](https://github.com/galactiC-reformeR/ttf2_coyote/issues/new/choose)（有模板）；
- 强度越界、急停失效、误触发这类：走 [SECURITY.md](SECURITY.md) 的私密报告，**不要开公开 issue**。
